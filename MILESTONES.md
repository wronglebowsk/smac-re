# MILESTONES — SMAC reverse engineering (hit-able plan)

**Target:** a reimplementation that plays solo against faction AI, on modern hardware, with the
menus and game UI recreated. Everything below serves that; anything that does not is out of scope.

**Rule that makes a milestone "hit":** it is done only when a **reproducible command or artifact**
proves it — a script that runs, a file that round-trips, a trace that matches. "I read the code and
it looks like X" is a finding, not a milestone.

**Rule that keeps us from stalling:** any milestone that runs past **2 sessions** gets split, and
the remainder is written down before the session ends. Context is the scarce resource, not ideas.

## Chapter C — Core mechanics, one system at a time (8–12 sessions)

Each C milestone has the same shape and the same kind of proof: **a prediction checked against the
running game**. That is what makes them hittable rather than endless reading.

**C1. Turn engine.** Done when `TURN_MODEL.md` explains what advances between turns (order of the
end-turn chain, who runs when) and `scripts/predict_turn.py` reproduces the year/energy/flags for 20
turns of an unmodified game.
**C2. Units & orders.** Done when the driver issues one real order (move a scout, set a base's
production) and the state reader proves the effect — this closes the "automation never plays" gap.
**C3. Base production & economy.** Done when mineral/energy output of a base is predicted for 10
turns from its population/tiles.
**C4. Research & tech.** Done when choosing a tech predicts the discovery turn from `alpha.txt` rates.
**C5. Combat & morale.** Done when a scripted fight's damage matches the observable outcome
(repeat 3× because of randomness; record the roll distribution).
**C6. Faction AI.** Done when an AI faction takes visible actions (expands, builds) for 50 turns with
no player input, and the driver logs what it did.

Stop rule: if a C milestone needs a new mechanic to explain itself, **write the dependency down and
move to a milestone it depends on** rather than expanding scope mid-session.

## Working agreement (why the last ten sessions went the way they did)

1. **One milestone per session**, evidence file written before the session ends.
2. **A milestone is closed by a command**, not by a conclusion. Save the command in `PROOF.md`.
3. **Two-session tripwire.** Over budget ⇒ split, log the remainder, stop.
4. **Prefer the cheapest oracle:** memory read > OCR > screenshot > reading decompiled code >
   guessing from strings. We have been burned by every guess.
5. **Never build on an unverified number.** (Today: a "w×h" decoder signature that was really
   size×count, and a "self-modifying exe" that was an RVA/VA mixup.)
6. **Absence claims need a positive control.** "Zero hits" only counts with a breakpoint that did fire.
7. **Keep the game process clean:** preflight `ptrace_scope=0`, kill `winedevice.exe` orphans, never
   Escape a title screen (it exits the game).
