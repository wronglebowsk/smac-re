Findings are limited to material defects in the PR diff.

1. **P1 — `sim/composedsave.py` (`run`, boundary branch) — the “smuggler is blind” falsifier never exposes the smuggler to the poison.**  
   The code skips `_poison_hand` for `mode == "smuggle"`:

   ```python
   if mode not in ("smuggle", "late") and poison and parent_idx is not None:
       img, edits = _poison_hand(img, parent_idx)
   ```

   G6 then requires:

   ```python
   sm["final_sha"] == cl["final_sha"]
   ```

   But `sm` is run with the poison skipped, while `cl` is the clean run. So “blind” is trivially true because the smuggler was never shown the poisoned boundary image. The claim in BUILD_SPINE/NAMED is that the model-object-reusing run is blind to boundary-image poison; the shipped instrument does not test a model-reusing run on poisoned bytes. MU14 reddens G6 by removing the exclusion, but that only proves the current G6 can break if the smuggler is made dirty, not that the shipped smuggler is blind under poison. This is a core falsifier defect: the gate is comparing two clean controls, not a smuggler exposed to the falsifier.

2. **P1 — `NAMED.md` B26 MODELED row cites `evidence/b26_selftest.txt:11` and `:55`, but the claimed `size_delta == 304·Δbases + 52·Δunits` law is not gated.**  
   The evidence line `:11` is the printed table-A relation:

   ```text
   the container grows only through the writer: size_delta per round vs ...: [(304, 304), ...]
   ```

   That line is produced by `render()` simply computing:

   ```python
   [(r["size_delta"],
     304 * (...n_bases delta...) + 52 * (...n_units delta...))
    for r in ...]
   ```

   No gate compares those tuples or asserts the per-round identity. G7 only checks that raw byte diffs lie in modeled spans. The VERIFIED claim includes “per-round size_delta == 304·Δbases + 52·Δunits in 6/6 rounds”, but that fact is printed, not read by a shipped gate. It is decoration under the repo law.

3. **P2 — `sim/composedsave.py` G1 — prose claims accepted and refused press counts match B25, but the gate only compares accepted counts.**  
   BUILD_SPINE and the gate label say accepted/refused press counts equal B25’s numbers. The gate boolean is:

   ```python
   [r["acc_save"] for r in c["rows"][:RA]] ==
   [r["accepted"] for r in m["b25_rows"][:RA]]
   ```

   There is no comparison of `refused` counts, and the B25 rows’ refused values are not consulted. A change that preserved accepted counts but broke refused counts would keep G1 green while contradicting the claim. If the refusal law is part of the claimed reuse, it must be measured or the claim must be weakened.

4. **P2 — `sim/composedsave.py` G5 and evidence line `:53` claim “unit-array x-bytes”, but the gate does not measure x vs y coordinates.**  
   The gate checks:

   ```python
   len(d1) == BYTES_SPLIT
   sum(1 for x in d1 if x < span[0]) == 0
   ```

   and `len(moved) == UNITS_SPLIT`.

   That proves “no header bytes differ” and a byte count, not that the differing bytes are coordinate x fields. The printed G5 text says “all of them unit-array x-bytes”, but no offset-level classification is asserted. The divergence could be in y bytes or other unit-array bytes with the same count and the gate would still pass.

5. **P2 — `sim/composedsave.py`, split-mode mid-gesture reload does not fully discard/rebuild the engine.**  
   The rung claims the boundary discards ledger, unit list, turn engine, and arrival list. At the normal round-aligned boundary it does rebuild `eng`. At the mid-gesture reload it creates `e2` but then never assigns it back:

   ```python
   e2 = soturn.Engine(imn.year, human=imn.own_player)
   ...
   base_im, model, led, arrivals = imn, md, led2, []
   ```

   The loop’s later `_write(... eng, ...)` still uses the pre-mid-reload `eng`. Therefore the split/budgetcarry non-carry measurement is not a true save/load of every modeled object at the split point. It may not affect the observed numbers, but the declared experiment is narrower than the prose and can hide additional non-carry state.

6. **P2 — `sim/composedsave.py` G3 “rebuilt ledger” is only length-checked, not checked against the loaded base fields/order.**  
   The code rebuilds the ledger from parsed image bases:

   ```python
   led = sobf.Ledger([... for b in im.bases])
   ```

   but G3 only asserts:

   ```python
   cb["rebuilt_ledger"][0] == cb["rebuilt_ledger"][1]
   ```

   That is a count equality. A mutation that re-seeded from the model but happened to preserve the same count would satisfy G3. If the claim is that the resumed run’s ledger is the image-derived ledger, not merely the same size, the gate must compare the fields/order the writer later uses, or the claim must be reduced to “count equals image count”.

7. **P2 — `sim/composedsave.py` G6 base-channel poison verifies the arrival’s parsed tile/own4, not the composed arrival record bytes.**

8. **P2 — `scripts/b26_np_add.py`, `b26_np_close.py`, `b26_np_trim.py`, and `b26_rebase_fix.py` are committed one-shot document-rewriting scripts.**
