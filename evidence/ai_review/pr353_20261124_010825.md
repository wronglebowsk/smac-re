## Findings

1. **P1 — `NAMED.md:59` / `scripts/m335_named_rotate.py:158-160`: the M248/M249 archive citation is wrong, and the rotate script’s assertion hides it.**  
   The stub says `docs/named-archive-m246-m254.md:218`, but the archive is only 94 lines and the M248/M249 block starts at line 21. The bug is in the placeholder substitution: for `## M248/M249 `, the key extraction produces `ARC_M24`, so `ARC_M248` becomes `<mark>8` (`21` → `218`). The guard `assert str(marks[h]) in t` passes because `"21"` is a substring of `"218"`. This corrupts the evidence pointer for a governed stub and means the rotation script can emit false archive line citations while still “passing”.

2. **P1 — `scripts/m335_difficulty_ladder.py:154-170` (`_g4`): the ORDER claim is not actually gated as an order claim.**  
   The NAMED row says the chooser “walks FORWARD appending `label[k]` with `push edi`=k, then seeds the dialog with `ds:0x985aec` before `call 0x5f1394`”. `_g4` only checks that a fixed set of fragments exists somewhere in the window: `mov esi,0x94d2ac`, `mov eax,DWORD PTR [esi]`, `push edi`, `add esi,0x4`, `inc edi`, `cmp esi,0x94d2c4`, `jl`, `call 0x60c555`, `mov eax,ds:0x985aec`, and `call 0x5f1394`. It does not verify forward loop order, that `edi` is the item index, that the seed load precedes the dialog call, or that the seed value is passed to the dialog. A mutation that moves the seed after `call 0x5f1394`, or changes the loop to walk backward while preserving the same fragments, would leave G4 green. The cited mutant set `{MU10,MU11}` only reddens fragment presence, not the claimed ordering semantics.

3. **P1 — `scripts/m335_difficulty_ladder.py:186-205` (`_g6`): “only clamp” and “hi == array END address” are not measured as claimed.**  
   The claim says the *only* clamp on the difficulty index is `FUN_00423af0(lo=0,hi=6)` and that `hi` equals the array END address. `_g6` checks one call site and one function body; it does not census all clamps, comparisons, or writes involving `ds:0x985aec` / `0x8f0c11`. It also does not compare the pushed `0x6` to the array END address; it only checks `push 0x6` and the hard-coded constant `(END-BASE)//STEP == 6`. The prose is therefore stronger than the instrument: the gate proves “there is a clamp with hi=6 at this site”, not “this is the only clamp”, and not “hi equals the END address” in any literal byte-read sense.

4. **P2 — `scripts/m335_difficulty_ladder.py:117-133` (`_g2`) and `:136-147` (`_g3`): the loader “fill” and “0 stores outside loader” claims are under-read.**  
   G2 checks the push site, the string `DIFF`, `mov esi,0x94d2ac`, `add esi,0x4`, `cmp esi,0x94d2c4`, and `jl 0x57ac79`. It does not read the actual store(s) that fill the table, nor that the loaded row pointer is written into `[esi]` or `[0x94d2ac + k*4]`. G3’s “stores=0” only inspects instructions whose operand text contains one of the base addresses or `0x94d2c4`, and only counts `mov DWORD PTR [...]` destinations. An indirect store through a register, a non-`DWORD PTR` store spelling, or a removed loader store would not necessarily be caught. The claim “loader … fill `0x94d2ac`” and “0 stores outside the loader” is therefore not fully backed by the shipped gate.

5. **P2 — `scripts/m335_difficulty_ladder.py:136-147` (`_g3`): the “all addressing forms incl. scaled” census is substring matching, not an addressing-form census.**  
   The gate scans for `hex(x) in o` over a fixed address list plus `"0x94d2c4" in o`. That can match an address inside a larger immediate or unrelated operand, and it can miss references where the base is materialized through `lea`, a register, or a different textual form. The claim says “census over all addressing forms incl. scaled”, but the instrument only proves that a hand-authored exact set of textual sites contains those substrings. MU13 changes the base textually, but it does not demonstrate that the matcher would find a genuinely different scaled/indirect addressing form.

6. **P2 — `NAMED.md:72` vs `docs/named-archive-m246-m254.md:41`: the M250 stub changes settled prose from “ADJUSTING WORLD CLIMATE” to “ALTERING WORLD CLIMATE”.**  
   The archive row says `FUN_005b09b0` is the “ADJUSTING WORLD CLIMATE” stage. The governed stub says `FUN_005b09b0` = `ALTERING WORLD CLIMATE`. If the stub governs, the milestone text has silently changed during rotation. If the archive is authoritative, the stub is wrong. Either way, the rotation is not faithful for this claim, and the contradiction is inside the NAMED evidence chain.

7. **P2 — `NAMED.md:62` / `docs/named-archive-m246-m254.md:30`: the M248/M249 stub weakens a boundedness claim.**  
   The archived row says `x` wraps mod `DAT_0092a378`, and `y` is *only* bounded by `DAT_0092a37c`. The stub says `x` wraps mod `0x92a378`, `y` bounded by `0x92a37c`. Dropping “only” changes the semantics from “no wrap / only this bound” to a generic bound, which could imply wrapping or other bounds. Since the stub says “this stub governs”, the compressed text must not alter the measured boundary condition.

8. **P2 — `scripts/m335_mutate.py:104-107` (`mu5`): the alpha-row swap mutant is line-ending fragile and can silently become a no-op if the shipped file uses CRLF.**  
   `ALPHA.replace("Citizen,\nSpecialist,", "Specialist,\nCitizen,")` assumes LF. The instrument reads `alpha.txt` with `errors="replace"` and `alpha_rows()` strips `\r`, so the census can pass on CRLF data while this mutant fails its own `assert a != ALPHA` or, worse, future changes could make the mutant ineffective. A mutation harness that depends on exact newline bytes should normalize or patch the parsed row list, not the raw text, if the claim is about row order.

9. **P2 — `scripts/m335_difficulty_ladder.py:172-183` (`_g5`): the “two readers bound their walk at immediate 6” claim is only a presence check at two hard-coded addresses.**  
   G5 checks that instructions at `0x484CB3` and `0x485410` are `cmp ...,0x6`. It does not verify that those comparisons are loop bounds, that the loops walk the difficulty table, or that the bound is used to stop at six entries. The claim reads like a semantic census of reader loops, but the gate only pins two textual `cmp` instructions. MU12 reddens the exact address, but a different loop-bound mutation elsewhere would not be caught.

10. **P2 — `scripts/m335_named_rotate.py:158-160`: the archive-line assertion is substring-based and therefore unsafe for numeric citations.**  
   Even apart from the M248/M249 bug, `assert str(marks[h]) in t` can pass when the stub contains a different number that merely contains the expected mark as a substring (`21` in `218`, `1` in `12`, etc.). For line citations, the script should require an exact token match, e.g. regex `(?<!\d)21(?!\d)` or a structured placeholder replacement, otherwise the rotation tool can certify false evidence pointers.
