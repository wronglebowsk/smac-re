P1 — `scripts/m384_bit400_writer.py:697-700`
The G7 digest is not the digest of the claimed “42-row pair-write table”. The digest body is built as:

```python
"0x%x:0x%x:%s:0x%x" % (a, b if isinstance(b, int) else 0, c[0], c[3])
```

but `b` is the destination string, so it is always hashed as `0`, and `c[3]` is the XOR mask, not the set/clear/arith/path/source/destination data. The printed digest is therefore a weak address/kind/xor digest, not the table digest cited in `NAMED.md` and `SESSION_NOTES.md`.

P2 — `scripts/m384_bit400_writer.py:437-452`
`resolve_mask()` mishandles `and` and `add` when decoding pushed mask arguments. For `and reg, imm` it returns `~imm` as the resolved mask bits, which is not the value of the register and can invent bits. For `add` it treats the immediate as a bitwise set mask, ignoring carries. This is an argument-decoding correctness bug; even if the current evidence does not exercise it, it makes the mask census unsound under mutation or future input.

P2 — `scripts/m384_bit400_writer.py:184-190`
The pair-pointer dataflow re-applies stack-slot seeds at every instruction:

```python
cur.update({("s", k[1]): v for k, v in seeds.items()})
```

so a slot seeded once as a pair pointer is restored even after it is overwritten or after a call. This can over-approximate “stores through a lea-derived pair pointer” and makes the G2 count dependent on an unsound liveness rule.
