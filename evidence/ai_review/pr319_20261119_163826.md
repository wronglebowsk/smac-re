**Why it matters:** repo law is that VERIFIED claims need a shipped gate reading the claimed fact. The exact digest is the reproducibility anchor for the rung; making it “V” while the gate only proves internal equality is exactly the “digest cited but not gated” failure mode.

**5. P2 — `sim/composedmove.py:231-238` — `out_written` can count records outside the container grid using `n_units`, while `found_units` is treated as parser acceptance.**  
The out-of-grid write arm is:

```python
wt = _tiles(im_w)
for i in model:
    if wt[i][0] >= W_cont or wt[i][1] >= H_cont:
```

and `_tiles` uses:

```python
return {i: [im.unit(i)["x"], im.unit(i)["y"]] for i in range(im.n_units)}
```

Meanwhile the parser’s rejection signal is `found_units`. If `parse_image.n_units` remains the declared count while `found_units` drops to 4, `_tiles` is accessing records that the parser has already declared invalid. The NAMED/BUILD prose frames the coordinate-space law as “arbitrated BY THE DECODER” and that `found_units` drops. That is true for `found_units`, but `out_written` is not purely decoder-arbitrated; it is the instrument’s own bounds check over all declared units.

**Why it matters:** the claim “the container owns the coordinate space” is gated partly by the instrument re-implementing the bounds condition. If `sim/save._unit_ok` and `_unit_ok`’s bounds logic diverge, `found_units` and `out_written` could tell different stories, while G5 only requires `out_written > 0` and `min_found_units < n`.

**7. P2 — `scripts/b25_mutate.py:93-102` — `gates` set extraction from `BAD:` is fragile enough to silently merge unrelated gate names.**  
The harness collects failed gates as:

```python
gates = set(re.findall(r"G\d+", bad)) - {""}
```

Gate names in `composedmove.gates()` are strings like `"G1 ..."`. That is fine if output only contains gate names, but it does not require that `len(gates)` equals the number of failed rows or that each gate name appears once. The earlier line:

```python
sum(1 for r in res if not r[1])
```

is used only in the printed suffix. If a failed gate text accidentally contains another gate label, the harness could score a mutant as redening an unintended set. The current output looks clean, but the scoring logic is not exact over `(row_index/name, ok)` pairs.

**Why it matters:** mutation harness correctness is repo law. Declared gate sets are supposed to be measured from the gate identities; regex-scraping all `G\d+` tokens from arbitrary failure strings is weaker than collecting gate names from `res` directly.

**9. P2 — `evidence/b25_selftest.txt:26-36` / `sim/composedmove.py:334-347` — blindness controls are “clean image byte-for-byte” but the final equality is compared to `container:clean`, not to the unpoisoned original save.**

where `cc` is `container:clean`. NAMED prose says the model-fed and read-after-write movers “rebuild the CLEAN image byte-for-byte.” That is correct relative to the clean composed container, but the stronger “not the original save” is not directly asserted. **Why it matters:** the falsifier’s point is that the model-fed mover is blind to the image-only poison. The gate proves blindness by byte equality to clean, but not independently that the poison byte reached the final container in the poisoned run before model overwrite? G6 final tile equality partly does. Still, the prose should be clearer: they are blind to the falsifier, not blind to writing. This is a measurement prose precision issue, not fatal.

**10. P2 — `NAMED.md:1358` / `SESSION_NOTES.md:227-231` — “read not vacuous” is gated only by round-0 save equality and later non-equality, not by all later tiles being writes of this run.**  
G4 vacuity check:

```python
moved[0] == n and all(v == 0 for v in moved[1:])
```

This proves that in rounds 1-3 no unit’s container head equals the original save tile. But it does not prove the current head equals the **previous round’s written container** except through `bad == 0` plus the mode assignment. The prose says:

> the container holds the save's tile for 67 records in round 0 and **0** later (read not vacuous)

and “from that reloaded tile the recorded delta and budget still hold.” The “not vacuous” claim is really “later head tiles are not equal to the original save.” If a unit legitimately returned to its original coordinate due wrapping, this gate would fail even though reload from container is still non-vacuous; conversely, if an earlier mutation caused stale container heads that still happened to differ from the original save, the vacuity clause would pass.

**Why it matters:** “read not vacuous” is a load-bearing claim for persistence. The measured condition is a narrow proxy, not the full reload law.
