1. **P1 blocker — the mutation harness does not implement its advertised “exactly measured gate set” check.**  
   `scripts/b27_mutate.py:1-198` declares `MUTANTS` as `(id, target, old, new, what)` with **no expected gate list**, and the scorer only checks that each mutant reddens *at least one* gate: `scripts/b27_mutate.py:169-175`. The docstring at `scripts/b27_mutate.py:7-10` and the ACCEPT row in `NAMED.md:1443` claim the harness “exits non-zero unless a mutant reddens EXACTLY its measured set.” It does not. A mutant can redden a gate unrelated to the claimed law and still pass; conversely, a gate can be reddened only by an unrelated mutant while its named claim mutant misses it, and the harness would not notice. This invalidates the repo requirement that every `V` row name a mutant that reddens *that* gate.

2. **P1 blocker — `G7` does not gate the claimed “refund leg measured inert on this save” fact.**  
   `NAMED.md:1438` says both legs are measured inert on the save: settle 0/8 and refund 0/8 because the container difficulty dword is `2 <= 3`, citing gate `:73`. But the shipped `G7` condition in `sim/composedenergy.py:412-417` only checks the synthetic ordering fixtures and `m["ord_save"] == 0`. There is no measurement that `sen.refund(...)` on the save’s actual blocks at `m["difficulty"]` returns no refund, and no gate pins the difficulty read to be the claimed `0x985aec` value. The instrument prints the difficulty at `evidence/b27_selftest.txt:2`, but that print is not a gate. A wrong difficulty read, or a changed `G_DIFF` constant in `sim/energy.py:60`, could still pass as long as the ordering fixture law holds.

3. **P1 blocker — `G1` “leg pin” checking is only substring presence, not operand/instruction binding.**  
   `sim/energy.py:50-75` defines pins as address or literal strings, and `sim/composedenergy.py:318-325` greps the cited evidence text for each address. It never checks that those addresses correspond to the claimed operands, nor that the module actually uses them. The spine says “address + operand tuple” (`BUILD_SPINE.md:913-915`), but the operand tuples are absent from `LEG_PINS`; only the refund switch tuples are separately parsed for `G6`. Thus `G1` can stay green if a pin is transcribed correctly but attached to a different field, or if the module silently stops using a pin. The negative control is also not “in the same list”: `sim/composedenergy.py:322-324` checks hardcoded `"0x5a1234"` against the cited files, rather than adding a fake pin to the pin list and measuring it in the same pass.

6. **P2 should-fix — `G4`’s “idle reproduced through THIS pipeline” is a tautology and does not test the recorded economy law.**  
   The idle parity is computed at `sim/composedenergy.py:266-271` by feeding the already-recorded energy value through `round_legs` with `gross=0`, `feed=0`, `debt=0`, and `spend=0`. In that state, `round_legs` necessarily returns the input energy unchanged (`sim/energy.py:133-150`). The gate at `sim/composedenergy.py:401-404` therefore verifies that `round_legs` preserves a constant, not that B4’s economy pipeline reproduces the idle trace. The real B4 replay is present via `_b4_inprocess` (`sim/composedenergy.py:328-338`), but the claimed “through THIS pipeline” idle parity is measured in a way that cannot fail on any idle sequence.

7. **P2 should-fix — the `smuggle` rival metric in `G10` is indirect and can represent the wrong thing.**  
   `sim/composedenergy.py:242-245` computes:
   ```python
   n_poc_carried = sum(1 for f ... if sm_rows[f] != ho_rows[f])
   ...
   ("smuggle", "...", abs(n_poc_carried - len(m["pz_facs"])))
   ```
   For the intended clean/blind smuggler, `n_poc_carried == 0`, while the poison-only run reaches one faction, giving a positive “bite.” If the smuggler loses blindness and also propagates the poison, `n_poc_carried` can become equal to the honest poison count, making the rival bite `0`, even though the falsifier/smuggler law has been defeated. `G9` catches the blindness case, but `G10`’s printed rival table is then measuring a counterintuitive difference-of-counts rather than the claimed property (“the smuggler reaches poisoned factions like the honest run”). This weakens the rival table as a diagnostic and risks a future refactor producing a misleading `0 = decoration` row for the wrong reason.

8. **P2 should-fix — the spine’s “three file-offset tables” claim is overstated; only two offset tables are parsed and gated.**  
   `BUILD_SPINE.md:913-915` says `G2` checks “the three file-offset tables.” `NAMED.md:1435` says “both file-offset tables.” The implementation only checks `+300` and `+224` file-offset parity: `sim/composedenergy.py:105-113`, `348-351`, and gate condition `sim/composedenergy.py:396-400`. 9. **P2 should-fix — determinism is not pinned as the claimed “printed tables + final container” identity.**  
   The spine says `G10` verifies “two runs → identical printed tables and identical final-container sha256” (`BUILD_SPINE.md:927-930`). The code checks only row-digest equality and final container equality (`sim/composedenergy.py:429-433`), and pins `m["digest"]` to `ANCHOR` (`sim/composedenergy.py:35`). `ANCHOR` is a digest of row tuples, not the printed output or final-container sha. Thus non-row output drift, e.g. label/table formatting or a changed top-line difficulty print, would not affect the anchored digest, even though `G10` is presented as guarding the run’s printed determinism.

10. **P2 should-fix — `G8` overstates byte-span checking as “every round,” but only the final written image is checked against modeled spans.**  
    `BUILD_SPINE.md:925-926` and `NAMED.md:1441` say “every round’s re-parse equals the model, every differing byte lies in a MODELED span.” The carry check is per-round (`sim/composedenergy.py:167-174`), but the outside-span check uses only `m["run"]["rows"][-1]` and one final `build_image` (`sim/composedenergy.py:227-233`). If an intermediate round wrote bytes outside the declared spans while the final round corrected them, `G8` would still pass. The writer law should be measured against each round image, or the claim should be narrowed to the final image.
