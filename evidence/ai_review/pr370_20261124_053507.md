## Findings

1. **P1 — `scripts/m347_named_rotate.py:20-21` moves more than B26 and leaves no registry stubs for M327/M329**  
   `START = "## B26 ..."` and `END = "## B27 (s309 BUILD"`, so the rotated blob includes `## M327` and `## M329` as well. The NAMED diff removes those headings entirely, while the stub only says B26 was rotated. The archive file is named/headered as the B26 governing block but actually contains three blocks. This silently drops two settled milestone headings from the registry that future greps/`named_registry_restore.py` will treat as missing. The rotation instrument’s `--verify` only checks the archive sha1 from `START`; it does not verify that every moved heading has a stub or that NAMED’s heading set changed as claimed.

2. **P1 — `NAMED.md` B26 stub misstates the archived OPEN row**  
   The stub says the only OPEN row left is “what the 19 record bits MEAN … and who fills the scratch `+0x00..+0x18`”. That is M329’s OPEN row, not B26’s. The archived B26 OPEN/UNMODELED row is different: one mid-gesture non-carry configuration, unmodeled in-progress turn state, inferred grown-record modeling, unexplained `found_units` collapse, exposed smuggler owner count, etc. Because the stub “governs”, this changes the settled B26 record and hides the real B26 caveats.

3. **P2 — `scripts/m347_page_writer.py` G4 does not gate “4 calls”**  
   The claim is “4 calls, receiver = lea[reg+0x5970] x3 + abs 0x74df70”. G4 only checks four hardcoded call sites have the expected receivers (`lea_n == 3 and mov_n == 1`). It never verifies that those addresses are calls to the sub-object functions, nor that there are no additional HoF calls into `0x629169`/`0x6291a3`/`0x6291e3`. A missing/extra call or retargeted call can keep G4 green.

4. **P2 — `scripts/m347_page_writer.py` G5 does not actually read “counter reloaded AFTER inc”**  
   `pre_inc` checks address ordering and the store/reload operands, but it never checks that `0x4493c8` is an `inc` or that it increments the counter used for the id. It also does not verify the `cmp`/`add` mnemonics used to compute `trip`. The gate can pass if the “inc” is replaced by another instruction or the loop arithmetic changes while the hardcoded addresses still line up.

5. **P2 — `scripts/m347_page_writer.py` G6 does not connect the player id to the selector call**  
   The claim is that the player writer passes `ds:0x91b5b4` / `[screen+0xa4c]` as the page id. G6 only checks that some instructions load `ds:0x91b5b4` and store it to `[esi+0xa4c]`. It does not verify that the select call at `0x44b72b` receives that value, nor that the block handler’s pushed id reaches the selector. The “writer” claim is therefore only partially measured.

6. **P2 — `scripts/m347_page_writer.py` G7 does not gate “unreachable from the 2 callers”**  
   G7 checks that there are no `cmp`/`test` guards on `ebx` between load and use and that sentinel indices land below `0x983a10`. It does not prove the `-1`/`-2` sentinels are unreachable from the two HoF callers. The NAMED row includes unreachability as part of the VERIFIED claim, but no gate or mutant reads that condition.

7. **P2 — `scripts/m347_page_writer.py` R2 rival is not fully gated**  
   R2 claims the textual census rival is dead because the 12 indexed `[r+r*4+0x59f4]` refs are in another array. The gate only checks `len(field_refs) == 1 and len(indexed) == 12`. It computes `off49` but never uses it. If the indexed refs moved into the HoF region or otherwise became relevant, R2 could remain green.

8. **P2 — `scripts/m347_page_writer.py` digest hashes mostly labels, not measurements**  
   `table_sha256` is computed from `ROWS`, whose entries are `(gate_id, static gate text, ok)`. Most measured values (`ids`, trip, receiver counts, sentinel addresses, indexed ref addresses) are not included unless they happen to appear in a few rival row texts. The cited digest can stay identical while measured literals drift, as long as the same gates still pass. This weakens the “digest x2” verification anchor.

9. **P2 — `scripts/m347_mutate.py` prints `uncovered []` without measuring coverage**  
   The harness checks that each mutant reddens its expected gates, but it never computes which gates are reddened by at least one mutant. The final line hardcodes `NO-OP [], uncovered []`. A gate with no mutant can still produce a passing harness report claiming no uncovered gates.

10. **P2 — `skill/scripts/named_registry_restore.py` still collapses duplicate identical headings**  
   It uses `cur_heads = {h for h, _ in cur_secs}` and `dict(src_secs)` for bodies. If two registry headings are byte-identical full lines, the script treats them as one and restores only the last body. The new git-workflow text specifically warns about duplicate `## (ARCHIVE)` headings; the restore tool should key by occurrence/index or otherwise preserve duplicate identical headings, not just by full heading string.
