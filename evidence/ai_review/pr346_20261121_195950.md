P2 — Clean-copy sites are pinned, but “no intervening write” for the copied memory cell is not enforced  
`scripts/m332_difficulty_census.py:253-289`, evidence `:11-18`  
The copy law says: load a cell into a register, then store that register to another cell, with no intervening clobber. Code kills register provenance on register redefinition and calls, but it does not kill or inspect writes to the source cell itself. For a pair like `0x92bde8 -> 0x985aec`, if the source cell were stored between the load and the store, the reported relation could be false, yet `COPY_SITES` and `G4` would still pass because the exact load/store addresses remain present. This weakens the measured DEFINITION behind “clean-copy map” and especially the master→runtime mirror claim.

P2 — The harness selftest’s “exactly one declared NO-OP” is weaker than it reads  
`scripts/m332_mutate.py:92-105`, evidence `:16-19`  
`ST4` requires `noops == ["MU16"]`, which is fine for declared no-ops. But the final harness success only requires each mutant’s observed red set to equal its declared set. `MU16` is declared `set()`, and evidence shows it reddens `[]`. However, a mutant that reddens nothing because it targets a site that is not read by any gate is indistinguishable from a declared NO-OP. The harness measures declared-vs-observed agreement, not “this mutant touches a measured literal/instruction consumed by a gate.” This is acceptable for explicitly declared NO-OPs, but the repo law says every VERIFIED row must name a mutant that reddens the claim; rows whose claim includes unmeasured origin/API/decompiler facts can pass on adjacent structural redness only.
