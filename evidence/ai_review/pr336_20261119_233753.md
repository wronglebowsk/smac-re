### 4. **P1** — `add_proven()` is too weak to support “post-snapshot ENERGY stores are additions-only”

- **Where:**  
  - `scripts/m328_hurry_globals_census.py:217-226`
    ```python
    def add_proven(a, reg):
        """Most recent definition of reg at/before store a is an addition
        (add/adc/inc/lea) - scanned back <=4 instrs (DECLARED window)."""
        i = m326.AIDX[a]
        for b in reversed(m326.ADDRS[max(0, i - 4):i]):
            bmn, bops = m326.INS[b]
            bp = m326.split_ops(bops)
            if bp and m326.reg_of(bp[0]) == reg and bmn not in ("cmp", "test", "push"):
                return bmn in ("add", "adc", "inc", "lea")
        return False
    ```
  - Used in `post-snapshot ENERGY stores` and `G4`: `scripts/m328_hurry_globals_census.py:292-301, 398-404`
- **What is wrong:** The scanner only inspects the **first operand** of the last non-`cmp/test/push` instruction that writes a matching `reg`. It ignores:

  It can therefore return `True` for “addition” when the real dataflow is not addition-only, or return `False` for a real addition outside the tiny window. `G4` treats its output as measured truth.
- **Why it matters:** The “additions-only” part of the warning-unreachable claim is not robustly measured. A mutation harness can plant one narrow addition and green it while the semantic claim remains unsupported.
