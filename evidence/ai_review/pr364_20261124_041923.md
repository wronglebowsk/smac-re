P2 — `scripts/m342_completion_setter.py:69-75` — `container()` can misclassify addresses in the first indexed function.

```python
i = bisect.bisect_right([f[0] for f in fns], a) - 1
for j in range(i, max(0, i - 40), -1):
    if fns[j][0] <= a < fns[j][0] + fns[j][1]:
        return fns[j]
return (a, 0, "HOLE")
```

If `i == 0`, `range(0, 0, -1)` is empty, so the first function is never checked and any address inside it becomes `HOLE`. More generally, the loop excludes `fns[0]` whenever `i > 0` because the stop is `max(0, i - 40)`. This is a parser defect. It may not affect the current addresses, but it can silently corrupt function attribution for other inputs and weakens claims like “in exactly 2 functions.”
